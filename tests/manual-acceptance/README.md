# Manual Acceptance · 人工验收工具与清单模板

## 文件说明

| 文件 | 角色 |
| --- | --- |
| `manual acceptance.html` | **使用入口**：人工验收矩阵工具，导入 / 导出文件一律用它。 |
| `test template_20260926.md` | 清单 / 报告的格式模板（2026-09-26 M3 实例），**仅参考和备份，不建议直接使用**。 |

> **模板仅作参考与备份**：不要修改或覆盖 `test template_20260926.md`，日常操作只碰 `manual acceptance.html` 及其同名 .md。工具本体不再单独留副本——此前那份与使用入口逐字相同的 `test template.html` 已删除，需要恢复时从 git 历史取。

## 使用者操作

浏览器打开 `tests\manual-acceptance\manual acceptance.html` 导入导出文件：

1. 「导入 .md」载入清单（或用「最近导入」直接重读最近一周的文件，免重复选文件）；
2. 逐项执行验收，勾选验收状态、填实测备注与结论；
3. 「导出 / 覆盖保存 .md」把结果写回同名文件（绑定目录后静默保存 / 覆盖）。

## 命名与格式规则

- 导出 / 导入的 .md 一律命名为 **`〈html同名〉_〈YYYYMMDD〉.md`**，时间戳精确到当天；用 `manual acceptance.html` 时即 `manual acceptance_20260926.md`。
- 测试主题等元信息写在内容抬头，不参与文件名；取不到 html 文件名时才回退用测试主题命名。
- 导入要求：文件名守上述命名规则、内容守导出格式，二者都满足才提取。
- 旧命名 `〈主题〉_〈YYYYMMDD_HHmm〉.md` 已废弃，导入会被拒绝。

## AI 工作约定（必须遵守）

1. **写人工测试清单，必须照 `test template_20260926.md` 的格式**（只参考其格式，不改动它），结构逐字保持：
   - 标题：`# 〈主题〉 - 人工验收测试报告`；
   - 抬头引用块：**测试主题 / 归档时间戳 / 测试执行日期 / 测试环境基线 / 验收责任人 / 用例通过率**（归档时间戳为 8 位日期，如 `20260926`）；
   - `## 一、 综合验收结论与总备注`：最终验收结论 + 综合评估备注；
   - `## 二、 详细验收用例与引导核验记录`：每条 `### N. [TC-xx] 〈组号〉. 〈标题〉`，下含四行：**验收状态 / 预期标准 / 步骤引导 / 实测备注**，用例之间以 `---` 分隔；
   - 页脚：`*本报告由 Rhine Lab 人工验收矩阵自动化本地生成并导出 · 文件名：〈同名〉_〈YYYYMMDD〉.md*`；
   - 新写的清单：验收状态一律 `⏳ 待测试 (PENDING)`，最终验收结论写 `**⏳ 待测试 (PENDING)**`（可导入、可往返），人工判定后在三者中改写：`准予交付上线 (Approved)` / `有条件通过 (Conditional)` / `阻断驳回重测 (Rejected)`；**步骤引导要写完整每一步操作过程**，但只有需要验证的部分才列入验收。
2. 清单文件名用 **`manual acceptance_〈YYYYMMDD〉.md`**（与使用入口 html 同名）；人工导出会覆盖同一文件。
3. **人工验收执行、导出之后，必须阅读导出的同名 .md 文件内容**（`manual acceptance_〈YYYYMMDD〉.md`），据此掌握验收结论、失败项与实测备注，再做后续汇总或修复。

## 标准工作流

1. AI 照 `test template_20260926.md` 模板写出清单 `manual acceptance_〈YYYYMMDD〉.md`（全部待测）；
2. 使用者打开 `manual acceptance.html`，「导入 .md」载入清单；
3. 人工逐项执行，勾选验收状态、填实测备注与结论；
4. 「导出 / 覆盖保存 .md」写回同名文件；
5. AI 阅读导出后的同名文件，汇总结果。
